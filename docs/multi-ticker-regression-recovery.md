## Evidence and final outcome

The real pre-fix MSFT UI generation completed in 270 seconds and rendered accepted SEC Revenue/parent earnings/Assets/OCF. It did **not** call save: console reported critical validation failure and the rendered valuation panel exposed `STATEMENT_PERIOD_LENGTH_MISMATCH`.

Exact first defective boundary: `adaptSecCanonicalToFinancialStatements` initializes required `income.net_income` to `[]`. After correctly moving `NetIncomeLoss` into `net_income_parent`, issuers without `ProfitLoss` leave the total-income array empty beside 12 valid fiscal periods. `sanitizeStatementSection` correctly rejects that malformed shape; `validateAndPrepareReport.canPersist` consequently rejects the report. TSLA discloses `ProfitLoss` and overwrites the placeholder, hiding this generic adapter defect. This is a false structural failure, **not** a false rejection of the valid source fact. Fix: aligned `null` placeholders, with parent/common amounts still distinct. The strict length validator stays unchanged.

Second defective boundary: `calculateDeterministicConvictionScore` still requires legacy total-income arrays even when verified parent earnings are available. A scope-aware research reader restores that input and records its attribution explicitly; it does not substitute parent income into total/common-specific ratios.

## Before / after dossier (20 required findings)

1. **Exact root cause.** A valid source-scope correction exposed a malformed consumer shape: `NetIncomeLoss` moved to parent earnings, while the adapter retained an empty mandatory total-income array. This made completed non-TSLA research fail structural validation and skip persistence. A second legacy total-only dependency suppressed Conviction despite available verified parent earnings.
2. **Introducing boundary.** `secFinancialMapper.METRIC_SPECS` correctly distinguishes `ProfitLoss` (total), `NetIncomeLoss` (parent), and explicitly common earnings. `secLegacyAdapter.adaptSecCanonicalToFinancialStatements` failed to make its required placeholder period-aligned. `reportValidation.sanitizeStatementSection` then correctly detected the mismatch. The semantic-cleanup work is uncommitted in this checkout; attributing it to a single Git commit would be misleading.
3. **Why TSLA worked.** Its filings disclose `ProfitLoss`, which overwrote the empty placeholder. The previously privileged growth-model ticker allowlist was a separate pre-existing defect, not the observed save failure. It has been removed; model selection now uses the latest growth observation, with a ticker-independence regression test.
4. **Why other issuers appeared sparse.** MSFT/AAPL have accepted parent earnings but lack a separate accepted total/common disclosure in these packages. SOFI also needs distinct earnings attribution and financial-company applicability. The malformed total array triggered a report-wide valuation/Conviction quarantine and skipped save; this amplified a small legitimate source-scope gap into a broad product failure.
5. **First incorrectly rejected fact.** No valid Revenue/Assets/OCF/parent-earnings source fact was found to be rejected at the SEC boundary in the reproduced controls. The first incorrect rejection was the assembled **report shape**, not the fact. MSFT's verified parent earnings remained present while `net_income: []` failed beside 12 periods.
